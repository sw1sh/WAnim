# WolfAnim — "Reanimate" Research & Design

Research and design notes for evolving WolfAnim (a 6-year-old Manim-style animation
framework in Wolfram Language) into a **live audiovisual coding** system that merges
declarative animation with Strudel/TidalCycles-style live-coding music on top of WL
15.0's new Computational Music + real-time audio stack.

## The three documents

1. **[animation-as-code-landscape.md](animation-as-code-landscape.md)** — a survey of
   the animation-as-code world (the Manim lineage in depth, Motion Canvas / Remotion /
   Theatre.js, Reanimate + FRP/Fran, creative-coding loops, and WL's own
   `Animate`/`Manipulate`/`VideoGenerator`/`Dynamic`), with every system mapped onto
   WolfAnim's existing `AnimatedObject`/`AnimationEffect` and the design patterns it
   should adopt (global transport, signals, declarative `Transform`).

2. **[livecoding-and-the-av-merge.md](livecoding-and-the-av-merge.md)** — the
   TidalCycles/Strudel **Pattern algebra** from first principles (query-over-a-timespan,
   cycles, mini-notation, the combinator zoo), the live-coding clock/hot-swap models
   (Sonic Pi, FoxDot, SuperCollider, ChucK, Extempore), and the central thesis: FRP's
   *"animation = function of continuous time"* and Tidal's *"music = function of cyclic
   time"* are **the same abstraction**. Surveys the audiovisual-merge systems (Hydra,
   Punctual, Estuary, flok, Gibber) and the verdict that **no system unifies sound and
   image around a single *symbolic* structure** — the gap WolfAnim can fill.

3. **[wolfanim-music-design.md](wolfanim-music-design.md)** — the flagship doc. **Half A**
   is a kernel-grounded review of WL 15.0's Computational Music framework and real-time
   audio/scheduling stack (with honest limitations and a kernel-verified quick-reference
   in §A.4). **Half B** proposes the design: one `Pattern` — a pure function of cyclic
   rational time queried over a timespan — that renders to **either** WolfAnim graphics
   **or** a `MusicScore`/`AudioStream` (one structure, two renderers), with a Tidal-style
   combinator + mini-notation layer, a non-blocking live-loop/hot-swap REPL, an audio↔
   visual bridge, three runnable demo sketches, and a phased roadmap on top of the
   current paclet.

4. **[dynamic-code-highlighting.md](dynamic-code-highlighting.md)** — Strudel-REPL-style
   live code highlighting inside notebook cells, now a **working prototype** (`LiveCode`):
   render the *symbolic* pattern as its own InputForm boxes and wrap each atom's box in a
   `Dynamic` `StyleBox` that flashes on its onsets, driven by the audio clock. Documents the
   mechanism, what's kernel-verified vs. needs a front end, the `$LiveAtomHeads` registry +
   separate `Strudel`` shortcut context, and next steps.

**Read order:** 1 → 2 → 3, then 4 once the pattern engine exists. Doc 1 frames what WolfAnim
is; doc 2 supplies the unifying abstraction; doc 3 turns it into a concrete WL design; doc 4
proposes the live-coding editor experience on top.

## How these were produced & verification status

Generated by a multi-agent research workflow (13 parallel finders across the three
territories → adversarial verification of the riskiest claims → draft-then-harden
synthesis), then hardened against a **live WL 15.0.0 kernel** (May 19 2026).

- **26/32** verified claims confirmed, **6 "partly"** (refinements — e.g. Manim's
  `lag_ratio` preserves group runtime but *not* via `squish_rate_func`; Remotion is
  frame-deterministic/seekable but not "pixel-identical"; Fran's `Behavior` is
  `Time -> a` only in its denotation; Tidal's default cps drifted from 0.5625 to 0.575).
  Zero outright refutations.
- The WL 15.0 API claims in doc 3 were re-tested directly in the kernel; §A.4 lists the
  confirmed facts. Anything still unverified is marked **(proposed/unverified)** inline,
  and each doc ends with its own flagged-claims / open-questions list.

### Known gap

The dedicated "audiovisual-merge" research finder failed (structured-output retry cap),
so the explicit survey of **Estuary / flok / algorave / TOPLAP** in doc 2 leans on the
visual-live-coding and pattern-UX finders rather than a dedicated pass. The conclusion
(no system unifies audio+visual around a single symbolic structure) is supported by the
Strudel/Punctual/Gibber primary sources that *were* gathered, but a focused re-run on
that finder would strengthen it.

## Most load-bearing finding

WL 15.0 already ships **every primitive** the design needs, verified on-kernel: a
symbolic music algebra (`MusicScore`/`MusicNote`/`MusicTransform`) that renders to
`Audio`, non-blocking hot-swappable `AudioStream` playback, audio-reactive analysis
(`AudioLocalMeasurements` on a stream's `CurrentAudio`), and a self-rescheduling
`SessionSubmit`/`ScheduledTask` clock that mutates globals a `Dynamic` can track. And
WolfAnim's `AnimationEffect` is *already* a pure function of normalized time — one short
reach from a Strudel `Pattern`. The pieces are all here; the work is the unifying layer.
